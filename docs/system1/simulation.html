Simulation — characters who know only what they should

status: designed, not yet implemented repo: planned src/simulation/ · CLI novel simulate model: work LLM (generation) + Jev (gates)

The payoff sector. A simulated character is not a persona prompt — it is a state folded from the event stream up to a point on a timeline (canon or a branch): what they know, feel, want, and how they speak, all derived from what actually happened to them by then. Talk to Mikoto before the confession and after it, and you talk to two honestly different people.

InputsCharacter + timeline/branch + current point · folded state · voice evidence (their turns, 06)
OutputsIn-character replies; new branch events when the conversation itself advances a branch's story
Depends on10 Storage (state fold), 11 Timelines (which world), 06 Turns (voice)
Feeds into11 Branches (conversation events can become branch deltas — via the merge discipline, not silently)

Design details

  • State = fold, never a row: emotions, knowledge, goals and relationships are computed by replaying events up to the point. Move the point, the person changes — on canon and on every branch, consistently.
  • Ignorance is a feature: the fold is also a wall. Facts from later chapters or other branches are not in the prompt, so the character cannot leak them.
  • Voice from evidence: speech style is grounded in the character's own attributed turns (06) — forms of address, verbal tics, sentence length — not in a hand-written persona sketch.
  • Jev as the referee: the same decision connector can gate replies — in_character (noul), would_say_this vs. alternatives (choice), divergence drift (score) — the simulation-side reuse of System 1.
  • Conversations can become canon-for-a-branch: when talk turns into story, the resulting events are branch deltas proposed through the same ChangeSet discipline — simulation never silently rewrites a world.

Implementation

  • State fold: OntologyStore.getStateAt() (10) over the timeline prefix (11).
  • Generation: the work LLM via src/connectors/llm.ts, prompted with folded state + retrieved turns + scene context from Ladybug hybrid search.
  • CLI surface: novel simulate <character> [--branch <id>] [--at <event-id>]; Discord later becomes a thin client of this command.

Open questions — simulation

  • Referee strictness.How hard should Jev gate replies — block out-of-character lines, regenerate, or just flag drift? Latency vs. fidelity per message is a real trade.
  • Multi-character scenes.Simulating a conversation among several characters (the legacy bot's group roleplay) — one fold per character, one speaker-choice per turn: reuse sector 06's question in reverse?
  • When talk becomes story.What threshold turns chat events into proposed branch deltas — every session, on user command, or when Jev scores a beat as event-worthy?
  • Voice drift over long sessions.Re-anchor to retrieved turns every N messages? Measure drift how?
