Extraction — from structured scenes to ontology

status: designed, not yet implemented repo: src/connectors/llm.ts (work model) · extraction step in the block processor model: work LLM (user API #1)

Everything before this sector is structure: sentences, scenes, turns. This is where meaning enters. The work LLM reads one structured scene at a time — never a raw chapter — and proposes the ontology: events, participants, causal links, and character state changes, all in the English-canonical schema, each with its evidence sentences attached.

InputsStructured scenes (spans, present cast, turns) + relevant graph context (who these characters are so far)
OutputsProposals appended to the block's ChangeSet: create_event, add_relation (CAUSES…), set_state_change, entity updates
Depends on02–07 (structure), 10 Storage (context reads)

Design details

  • Per scene, not per chapter: the old system extracted 3–5 events per raw chapter and lost the thread. A scene is small, cast-bounded, and already structured — extraction quality follows.
  • English semantics, original evidence: every event gets an English summaryEn (cross-language search and reasoning) plus the original-language quote and sentence IDs (provenance).
  • State is proposed as deltas: "Mikoto: embarrassment +0.3, knowledge += patrol schedule" — state changes are proposals like everything else; the canonical state is always a fold of merged events (sector 12).
  • Causality is explicit: CAUSES edges are first-class proposals with confidence, not list properties on nodes — the legacy design's known weakness, fixed here.
  • Same gate: extraction proposals join the patches' proposals in one ChangeSet per block. One review, one merge.

Implementation

  • WorkModel interface in src/connectors/llm.ts — target: Pi's provider layer (@earendil-works/pi-ai), so any user-provided LLM API works.
  • Extraction runs inside BlockProcessor between the miniloop and the merge gate (marked TODO in the skeleton).
  • Output validated against the English schema v1 (src/ontology/types.ts) before a proposal is admitted to the ChangeSet.

Open questions — extraction

  • Event granularity.How many events per scene is right? Too few and causality thins; too many and the graph drowns in trivia. The event-worthiness candidate patch (Jev score) could pre-filter — or extraction decides alone.
  • State dimensions.Which state does a character carry — emotions, knowledge, goals, relationships, location, possessions? The legacy design had all of these; the fold cost grows with each.
  • Causality: propose or originate?Should the causal-candidate patch pre-propose CAUSES edges for extraction to confirm, or does extraction originate them? Split of labor between Jev and the LLM is undecided.
  • Summary fidelity.summaryEn is a translation AND a summary. Spot-check workflow at the merge gate, or a confidence the LLM self-reports?
