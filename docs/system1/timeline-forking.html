Timelines & forking — parallel universes from one canon

status: designed (salvaged from the legacy timeline design), not yet implemented repo: planned src/timeline/ · types in src/ontology/types.ts decision assist: Jev · score / choice

Canon is an event-sourced timeline: immutable, totally ordered. A fork is what the user came for — they browse the timeline, select a time point, and a parallel universe branches off there: sharing everything before the point, diverging after it, with canon never mutated.

InputsThe canon event stream (10) + the user's chosen fork event + a branch label
OutputsBranch { parentTimelineId, forkEventId, label } + a character-state snapshot at the fork point; branch delta events thereafter
Depends on08 Extraction (events), 10 Storage
Feeds into12 Simulation (runs on canon or on a branch)

Design details

  • Fork = pointer + snapshot + deltas: a branch stores its fork event, a fold of character states at that point, and only its own new events. No copying the canon prefix — branches are cheap, so users can keep many.
  • Canon is never mutated: branch events live on the branch. Deleting a branch loses nothing canonical.
  • Browsing is importance-led: the fork-point browser lists events by chapter with their importance scores (extraction + the event-worthiness candidate), so the interesting seams surface first — but any event is a legal fork point.
  • Decision assist, not decision maker: Jev can score "how divergent would a fork here be" and match "which existing branch is this conversation closest to" (the legacy UniverseFingerprint idea, rebuilt on distributions) — the user still picks the point.
  • Salvaged design: the legacy repo's TimelineNode tree and branch auto-selection live on here, re-expressed on the event-sourced model.

Implementation

  • Types ready: Branch, CharacterStateAtPoint in src/ontology/types.ts; FORKS_FROM relation + Branch node table in schema v1.
  • CLI surface: novel timeline list|show, novel fork create --at <event-id> --label <name>.
  • State snapshot = OntologyStore.getStateAt(characterId, eventId) folded over the canon prefix.

Open questions — timelines & forking

  • Branch-of-branch.Forking from inside a branch — supported by the model (parent can be any timeline), but does the UX and the state fold stay comprehensible two levels deep?
  • Divergence measurement.How do we quantify how far a branch has drifted (event overlap, state distance, relationship deltas) — and does the user see a number, a summary, or both?
  • Branch discovery.When a simulation conversation drifts, should the system suggest "this now matches branch X" (legacy auto-selection at similarity > 0.6) or wait to be asked?
  • Canon updates under live branches.If ingestion later adds canon events before a fork point (a re-merge), do branch snapshots pin the old fold or re-fold? Pinning is safer; say so explicitly.
