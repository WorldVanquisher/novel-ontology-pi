Open questions — to plan together

The skeleton is shaped so each of these can be decided later without a redesign. They are listed here — and in DESIGN.md §9 — so the discussion has a home. Nothing below is assumed by the code unless it says so.

  • The patch catalog itself.Which candidate patches (addressee, state changes, event-worthiness, causal candidates, coreference, foreshadowing) earn a v1 slot? What functionality is missing entirely?
  • Name-candidate generation.How does the name detector propose candidate spans for new names — speech-verb patterns, quote-adjacent capitalized/CJK sequences, work-LLM nomination, or a mix? The patch interface is ready; the generator is not decided.
  • Revision granularity at the merge gate.When the main agent sends a ChangeSet back, is the unit of revision a single proposal, a scene, or a patch's whole output for the block?
  • Gate thresholds per patch.Accept / re-ask / escalate cut-offs (0.85 / 0.55 proposed) — to tune with the Jev test key on a golden chapter.
  • Window sizing.How many sentences per window, and how much scene context rides along as state, given Jev's ~32k-token context?
  • The first test novel.Which sample novel is the first end-to-end case — re-ingest the legacy Index corpus, or start with a shorter dialogue-heavy work?
  • Embedding provider / model.Choosing it locks the Ladybug vector index dimension; changing it later means a reindex job.
  • Jev access route.Direct api.typesafe.ai vs. a gateway (OpenRouter / Vercel) — settled when the key is handed over, via secure entry.
  • Simulation-side reuse.The same Jev connector can gate roleplay later (in-character checks, fork suggestions, branch matching) — designed now or later?
