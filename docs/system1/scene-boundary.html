Scene boundary — where scenes start

status: v1 patch (skeleton) repo: src/autostep/patches/scene-boundary.ts model: Jev · noul

Scenes are the unit everything else keys off: presence is per-scene, dialogue groups inside scenes, and extraction reads one scene at a time. This patch decides, sentence by sentence, whether a new scene begins — and records why.

InputsSentences of one window (IDs + text) + compact state: current scene-so-far
OutputsScene spans — ordered sentence-ID ranges, into shared context for patches 03–06 and extraction
Depends on01 Sectioning
Feeds into03 Dialogue, 05 Presence, 08 Extraction (per-scene unit)

Decision questions

is_scene_boundary · noul — Does a new scene begin at this sentence (change of place, a time skip, or a viewpoint shift from what came immediately before)? Asked per sentence; ≥ 0.5 opens a new span.
boundary_reason · choice candidate — location_changed / time_skipped / pov_changed / cast_changed. Knowing why a boundary fired helps presence decide carryover.

Design details

  • First patch in the registry — its spans frame every later patch's work in the window.
  • A boundary is a probability, not a cut: near-0.5 answers are exactly what the engine's re-ask gate (sector 07) exists for — expand context and decide again.
  • Spans, not copies: a scene is a list of sentence IDs; the text stays in the block, referenced.

Implementation

  • src/autostep/patches/scene-boundary.ts — builds one noul per window sentence; applies spans into ctx.accepted.sceneSpans.
  • Gates: accept ≥ 0.85 · re-ask 0.55–0.85 · escalate < 0.55 (tuning: see Open questions).

Open questions — scene boundaries

  • Granularity.Is a flashback inside a conversation a new scene, or a marked sub-span? Same question for dreams and回忆 interludes.
  • Soft boundaries.Same room, same cast, but an hour passes — one scene or two? The answer changes how presence carryover works (sector 05).
  • Reason taxonomy.Is {location, time, POV, cast} the right reason set — and does extraction actually consume the reason, or is it decoration?
  • Length caps.Extraction reads per scene; is there a max scene size beyond which a "soft split" is forced for context limits?
