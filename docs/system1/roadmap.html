Roadmap — implementation order & decision log

The work, sequenced. Each phase lists what gets built (with the sectors it touches), the milestone that ends it, and the open questions that get decided in that phase — nothing is decided earlier than it needs to be.

Update rule: this page is updated in GitHub every time something is completed — phase statuses and the decision log here are the project's progress record of truth. Phase 1 — Live, end to end, on one test novel ● in progress

  • Storage wiring (10) ✓ done — real Ladybug driver (@ladybugdb/core): schema DDL applied, bundle → graph build, parameterized Cypher
  • Cypher-sufficiency experiment (10) ✓ built — graph-only retrieval layer: presence, co-presence, causal ancestors/descendants, scene location, character event streams, fork points. Embeddings DEFERRED until one of these provably falls short
  • Block cutting (01) ✓ done — multilingual chapter detection + paragraph-boundary blocks (novel blocks)
  • Gate tooling (09) ✓ done — ChangeSet persistence + changeset list|show|approve|hold; approve applies to the bundle and rebuilds the graph (verified end to end in tests)
  • Model wiring (07/08) — Jev client live; DeepSeek as the work LLM via the provider layer
  • Extraction step (08) — per-scene LLM extraction inside the block processor

Milestone: one real chapter of Index → ChangeSet → main-agent review → merged into Ladybug → queried back.

Waiting on: Jev key handover (secure entry) · DeepSeek key · the Index corpus file. Remaining Phase-1 work is exactly the two items above without ✓.

Phase 2 — Miniloop quality planned

  • Name candidates, full build (04): cumulative per-novel name registry scan + zero-context LLM extraction for new names
  • Calibration (07): gate thresholds + window size measured on a golden chapter
  • Presence ranges (05): entrances/exits mid-scene · speech-tag attachment (03)
  • Story-so-far digest (07): cross-window memory in the state summary

Milestone: the miniloop's decisions are measured, not hoped — precision/recall known per patch.

Parallel track — Playground frontend (13): event emission from the CLI + Live Theater v1 on Reagraph, so ingestion becomes watchable as soon as live models land.

Phase 3 — Whole-novel ingestion planned

  • Gate at scale (09): revision granularity, review digest, cross-block consistency checks
  • Storage at scale (10): incremental Ladybug sync, multi-novel library layout
  • Robustness (01/02/03/04/06): damaged text, unquoted dialogue, style profiles, name collisions, cross-language merges, first-person narration, scene granularity

Milestone: a full novel ingested block by block, human hands only at the gate.

Phase 4 — The use phase planned

  • Timelines & forking (11): fork-point browser, branch creation, pinned state snapshots, divergence scoring
  • Simulation v1 (12): one character, folded state, voice from their own turns, Jev referee in flag-only mode

Milestone: pick a time point, fork the world, talk to someone who lives there.

Phase 5 — Expansion planned

  • Multi-character simulation (12) · branch auto-discovery (11) · auto-approval envelope (09)
  • Bundle-in-git (10) · candidate patches: addressee, state-change, event-worthiness, causal-candidate, coreference, foreshadowing
  • Discord as a thin client over the CLI

Milestone: the platform the original Discord bot wanted to be — on the new foundation.
