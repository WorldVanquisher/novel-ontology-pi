Miniloop engine — windows, batching, gates, recursion

status: implemented (skeleton) repo: src/autostep/miniloop.ts model: Jev connector · src/connectors/jev.ts

The patches (02–06) are the questions; this sector is the loop that asks them: it slides a window over the block's sentences, batches each patch's questions into one Jev call, routes every probability through confidence gates, recurses when uncertain — and collects everything into the block's ChangeSet. It is the "autostep" in System 1's name.

Gates are per patch (each patch declares its own accept/reask in code): presence holds the strictest line because it feeds simulation state; the engine only enforces the routing.

Design details

  • One call per window per patch: all of a patch's questions for the window go in a single batched Jev request with one compact state snapshot — never raw chapters (Jev's context is ~32k, and state summaries keep it fast and cheap).
  • Accepted decisions compound: patches run in registry order and read each other's accepted output from shared context — the engine's job is ordering and bookkeeping, not judging.
  • Escalation is a routing decision, not a failure: subdivided windows and LLM-adjudicated units come back into the same loop; their verdicts are written into context and the window advances.
  • The engine never writes: its only outputs are proposals and escalations. The hard invariant — enforced again at apply time in sector 09.
  • Testable for free: the Jev connector is an interface; tests inject a mock with recorded probabilities and verify gates, grouping and ChangeSet accumulation deterministically.

Implementation

  • src/autostep/miniloop.ts — Miniloop.runBlock(): window loop → patch loop → accumulate.
  • src/connectors/jev.ts — DecisionModel interface, JevClient (Bearer key from env, pinned model), MockDecisionModel for tests.

Open questions — the engine

  • Window sizing.40 sentences is the skeleton's default. Larger windows give Jev more context per question but dilute the state summary; smaller ones cost more calls. Tune on the golden chapter.
  • Threshold calibration.0.85 / 0.55 are starting proposals per patch. With the test key, we can measure real distributions and set gates from data, not vibes.
  • Escalation budget.How many LLM adjudications per block before the engine should stop and let the merge gate see the block as-is? A cost/quality dial the user may want control of.
  • Cross-window memory.How much accepted structure (last scene, last speaker, open threads) rides in the state summary — and does a "story so far" digest get maintained per novel?
